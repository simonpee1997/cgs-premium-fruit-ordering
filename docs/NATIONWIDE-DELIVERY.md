# Nationwide delivery and RM300 free delivery

Approved policy: delivery accepts all five-digit Malaysian postcodes. Product subtotals of RM300 or more after product discounts receive free delivery nationwide. Shipping and tax do not count towards the threshold. Smaller orders retain the saved delivery fee (currently RM30); pickup remains free.

Migration `008_nationwide_delivery.sql` verifies CHIPSTI's branch/business/SSM, preserves the complete existing delivery and catalogue function implementations as private backups, and replaces their original entry points without changing function OIDs. This ensures existing quote, placement and payment paths all use the authoritative updated delivery quote. It clears only CHIPSTI's postcode prefixes and scopes the new free-delivery adjustment to CHIPSTI's branch. Other business branches retain their original rules. Existing order/payment snapshots, inventory, prices, tax, bank and QR settings are not rewritten.

The catalogue advertises the capability only after the atomic database migration commits. The storefront uses that capability to show nationwide messaging and match server pricing; older catalogue fixtures retain legacy area calculations. Final checkout still verifies prices and totals on the server.

Deployment: `scripts/apply-nationwide-delivery.mjs` is a no-op on ordinary builds. The explicitly approved Vercel production deployment supplies `CHIPSTI_NATIONWIDE_DELIVERY_SHA` equal to its exact Git commit. The script uses the existing protected database integration, verifies the Supabase project and business, applies the reviewed migration, checks unchanged fees/settings, and tests read-only delivery quotes below and at RM300 for Peninsular Malaysia, Sabah and Sarawak. Credentials are never printed. Promotion migrations remain separate and uninstalled.

Validation: isolated PostgreSQL/PGlite execution covers original order preservation, stable function OIDs, nationwide quotes, RM299.99/RM300 boundaries, discounts, invalid postcodes, payment confirmation, anonymous permission denials and unrelated business isolation. Browser fixtures exercise exact checkout totals and postcode 93000 across desktop/tablet/mobile. Live verification uses quotes only; no test orders or payments are created.

Rollback: first preserve the current function definitions/configuration and confirm no concurrent owner edits. In a reviewed transaction, recreate the two original public entry points from `pg_get_functiondef` of their `before_nationwide` backups, replacing only the function declaration name; preserve existing execute grants and clear the nationwide version comments. Restore the former postcode prefix configuration (it was `["51200"]` before this release) only if reverting the restriction is intended. Do not rewrite orders placed during nationwide free delivery. Keep backups until rollback has been verified; restore the previous Vercel deployment if required. This rollback procedure is documentation, not an automatically executed command.
